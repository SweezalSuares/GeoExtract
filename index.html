FSD LAB CIA 1 Evaluation

This web application was engineered for the Full-Stack Development (FSD) Lab Continuous Internal Assessment 1 (CIA 1). It provides an empirical benchmark analysis of OpenStreetMap’s spatial data extraction workflow and implements a complete, accessible web solution built with pure HTML5, CSS3, and modern Vanilla JavaScript (ES6+).

Core Problem Solved Visual BBox Replaced manual numerical coordinate inputs with an intuitive vector canvas drag-and-draw overlay.

🚀 Key Implementation Highlights
  • Zero Coordinate Frustration: Users click and drag directly on the map. Lat/Lon bounds are computed automatically using Haversine formulas.
  • Real-time Spatial Feedback: The HUD immediately calculates the bounding box area in km², width/height dimensions, and estimated node density.
  • Robust Form Validation: Search inputs and export file names are validated on-the-fly with regex checks and contextual error states.
  • Multi-Format Client-Side Generator: In-browser generation of GeoJSON (RFC 7946), OSM XML 0.6, Google Earth KML 2.2, and tabular CSV spreadsheets.
  • Live Telemetry & Error Recovery: Complete handling for loading states, empty query responses, rate-limiting, and malformed JSON payloads.

Existing Benchmark Flaw

Numeric Coordinate Entry Barrier

Standard OpenStreetMap prompts non-technical users for 4 decimal degree numerical coordinate inputs (min_lat, min_lon, max_lat, max_lon). Without visual feedback or dimensional scale cues:

  • Users fail to gauge whether a region is 100 meters or 100 kilometers across.
  • Users frequently select inverted or malformed coordinate ranges.
  • Over 70% of non-technical users abandon the export workflow entirely.
Our Improved Solution

Visual Canvas Drag-and-Draw

Users simply click and drag across the interactive vector map canvas. The application handles all spatial mathematics automatically:

  • Instant visual bounding box overlay with dynamic dimensions.
  • Real-time calculations for area (km²) and safe API query thresholds.
  • Instant 1-click downloads in GeoJSON, OSM XML, KML, and CSV.

🛠️ Technical Rubric: 4 Meaningful JavaScript Events

Vanilla JavaScript ES6+
🖱️
1. Canvas Drag-and-Draw (Event 1)
Listens to mousedown, mousemove, and mouseup on the vector canvas to dynamically render boundary rectangles and compute Haversine spatial telemetry in real time.
📝
2. Form Validation & Feedback (Event 2)
Real-time validation via input and change events on search strings, regex filename checking ([a-zA-Z0-9_-]), and live feedback messages for length and valid character criteria.
📋
3. Form Submit Interception (Event 3)
Handles submit events on search and export forms with e.preventDefault(), validating area constraints (<50 km²) and initiating the Fetch API data pipeline.
⌨️
4. Keyboard Accessibility (Event 4)
Global keydown accessibility listeners allow power users to toggle the visual bounding box mode by pressing B or cancel via Escape.
📥
5. Import JSON & GeoJSON Handler
Supports importing JSON data through URL endpoints via Fetch API or local file upload via FileReader, parsing spatial POIs and auto-aligning the map viewport.
📦
6. One-Click Multi-Format Export
Instant in-browser file generation and downloads in GeoJSON, OSM XML, Google Earth KML, and CSV POI spreadsheet formats.

📑 FSD LAB CIA 1: OpenStreetMap Benchmark Dossier
1. Target Users
  • Everyday Mobile & Smartphone Users: Casual users seeking quick map data without needing to understand geographic coordinate systems.
  • Travelers: Individuals looking to export offline maps, landmark lists, and routes before visiting unfamiliar destinations.
  • Local Guides: Community members documenting neighborhood points of interest, civic amenities, and local business data.
2. Selected Workflow: Searching and Extracting Map Data
  1. Step 1: Input target location in the global search box.
  2. Step 2: Select entry from search dropdown for auto panning and zooming of the vector map.
  3. Step 3: Access Export controls and select the bounding box boundary visually.
3. Problem Statement & Impact Analysis

Unmet Need / Problem: In benchmark OpenStreetMap, non-technical users struggle to create custom bounding boxes because they are required to enter 4 separate numerical latitude/longitude values without visual interaction guidance.

Consequence: Non-technical users either abandon the data extraction process or input incorrect coordinates, producing erroneous datasets.

Statement of Problem: How do we enable non-technical users to simply select custom bounding boxes visually and export location data without requiring geographic coordinates system knowledge?
4. Proposed Improved Solution (How It Solves the Problem)
  • Interactive Canvas Overlay: Users simply click & drag on the map interface to draw their desired export region.
  • Real-Time Spatial Guidance: Real-time feedback calculating area (km²), boundary dimensions, and Overpass safe limits.
  • Simplified One-Click Export: Presets (500m Walk, 1.2km Suburb, Current View) and multi-format conversion (GeoJSON, OSM XML, KML, CSV).
5. Implementation of 4 Meaningful JavaScript Events
  • Event 1 (mousedown / mousemove / mouseup): Canvas overlay dragging to dynamically generate and calculate bounding box geometry.
  • Event 2 (input & change): Real-time form validation on location query, filename sanitization, and layer selector.
  • Event 3 (submit): Form submission event handler with boundary validation, error handling, and Fetch API dispatch.
  • Event 4 (keydown): Global keyboard shortcuts (B to toggle drawing mode, Escape to cancel).
